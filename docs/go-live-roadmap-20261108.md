## 〇、一句话：现在离上线有多远

## 二、最小可上线版本（MVP）长什么样

**收敛原则：保住「倾听 → 推荐 → 创作 → 分享」主环 + 安全红线，砍掉一切需要新资质或新运营能力的功能。**

**首发保留**：注册登录（先注册后校内人工核验）、情绪对话（SSE + 危机干预 + 免责声明）、心情便签、手作推荐（规则+RAG，AI 理由可降级）、图文步骤创作 + 心流/呼吸、作品先审后发、隐私中心（导出/撤回/注销）、管理端审核与关怀跟进。

**首发关闭/不展示**（开关或入口层收口，不删代码）：
- **语音输入/播放**（千问真实通话未验收）——`SPEECH_PROVIDER` 不配 key 即自动降级为文字输入，前端入口隐藏；
- **互助小组的公开招募**（如涉及陌生人社交类目风险，先以「校内邀请制」收口——待 §七类目结论确认后定）；
- **预约交流实时音视频**（本就不在范围）；
- **AI 线稿共创的对外宣传口径**（功能可留，但发布文案不作为卖点，降低算法备案面）。

**砍掉的判断依据**：每一项首发关闭的功能都对应「缺真实验收证据」或「增加资质/审核面」，而非功能不完整。

## 三、顺序与依赖

```
第 0 周（立即启动，全是等待周期，不占开发人力）：
  ├─ 主体决策：学校（事业单位）vs 企业主体 → 决定类目路径（§七）
  ├─ 域名注册 + ICP 备案（管局审核通常数个工作日到数周，估不准）
  ├─ 算法备案材料：与 DeepSeek（深度求索）确认合作协议 + 备案号引用方式
  └─ 心理中心/法务对接：热线引用授权、危机联动 SOP、合规文本评审

第 1~3 周（开发线，与资质线并行）：
  ├─ 危机词库扩充 + 漏判预案（M5，先行——红线）
  ├─ 生产配置清单 + 部署脚本（M3）
  ├─ 真实 AI 验收（M4，依赖正式 key 与额度）
  ├─ 真机验收（M7，依赖体验版小程序 + 已备案域名可先走 IP 白名单豁免期……
  │   注：体验版/开发版可用 urlCheck:false 调试，正式版必须域名就绪，故 M7 正式验收依赖 M2）
  ├─ 备份恢复演练（M8）
  └─ 监控最小方案 + 运营 SOP v1（S1/S4）

第 4 周起（提审线，依赖 M1/M2/M6 全部就绪）：
  ├─ 小程序提审（预留 1~3 轮被拒重提的缓冲）
  ├─ 灰度：先校内小范围（邀请制/白名单）→ 观察 2 周（§六）
  └─ 达标后全量
```

**关键路径**：主体决策 → ICP 备案 → 类目申请/提审。这条线上的每一步都被前一步卡住，且都不是开发能加速的——**本周内必须把主体和类目路径拍下来**。

## 七、专项：小程序类目与资质（最容易卡死的第一件事）

### 7.1 事实与调研结论（2026-11-08 检索微信平台公开规则）

织愈叠了三层敏感属性，每层对应不同监管面：

| 产品面 | 对应类目/监管 | 资质要求 |
|---|---|---|
| **AI 对话**（生成式 AI，拟人化陪伴） | 「深度合成-AI 问答」类目 | ① 个人主体**不开放**该类目，需企业/组织主体；② 提供算法备案：用第三方大模型（DeepSeek）需其技术主体的《互联网信息服务算法备案》+ 双方合作协议（协议须含算法名称/应用场景/备案编号）；③ 《安全评估报告》。另：2026 年《人工智能拟人化互动服务管理暂行办法》（网信办等五部门第 21 号令）对拟人化互动服务要求算法备案 + 安全评估 + 年度核验，心理陪伴类产品直接命中 |
| **情绪陪伴内容**（非诊疗） | **避开「医疗」类目**——心理咨询/问诊需《医疗机构执业许可证》，织愈没有也不能碰 | 文案必须守住「陪伴与引导、不诊断」红线（前端已实现），提审描述中不出现「心理咨询/治疗/测评」字样 |

## 九、专项：心理危机的责任边界（最容易出人命/舆情的一件事）

### 9.1 词库缺口（本次验证：静态通读确认）

high-risk.txt 现有 39 词，覆盖直接自伤意念（L2）、绝望感（L1）、具体计划行为（L3）。**缺的形态**：
- **告别类**：「永别」「再见了」「告别」「最后一封信」「交代后事」——高危评测语料中这类形态目前只能靠 AI 层兜；
- **求救类**：「救我」「求救」「谁能帮帮我」「SOS」「撑不住了」——语义上与绝望不同，是主动求助信号，漏掉等于错过最佳干预窗口；
- **英文/谐音/谐音变体**：当前词库纯中文子串匹配，「想 s」「紫餐」类变体为零覆盖。

已知事实（历史验证）：词库兜底覆盖率约 14%（105 条正例中 90 条靠 AI 层），即**当前体系实质上是「AI 为主、词库为辅」**——词库扩充要做，但不能假装扩充后就不依赖 AI 层。

### 9.2 兜底流程现状（已实现，历史验证）

词库命中即 BLOCK（不做 LLM 复核）→ 关怀话术 + 热线展示 + care_reminder 落库（脱敏摘要、加密）→ 咨询师/管理员按 scope 查看认领；危机路径永久直连、零 LLM、不落原文（dialogue 收敛设计）。审核 AI 层高危漏放率 0%（180 次真实调用，2026-11-05/07，样本有限不构成长期结论）。

### 9.3 上线前必须定的三件事（M5）

1. **词库扩充 + 评测复跑**：补告别/求救/常见变体形态，高危评测集同步扩样（L3 样本 n=12 → ≥60），复跑后更新漏放上界；
2. **漏判处置预案（文档化）**：一旦发生「用户出事后被发现曾表达高危信号但系统未拦」——封存该用户 ai_audit_log 与危机日志（只追加表天然支持）、48h 内完成根因定性（词库缺词 / AI 漏判 / 配置失效）、按结果补词库或调阈值、对外由学校心理中心统一口径回应（不是产品团队直接面对）、复盘记录进运营 SOP；
3. **真人联动确认**：危机话术里的热线与心理中心信息（当前默认江西师范大学）必须经该机构**书面同意**；明确「系统预警 → 心理中心老师认领 → 线下跟进」的 SLA（建议工作时间 24h 内认领），没有这个承诺，危机提醒功能就是给机构甩锅。
