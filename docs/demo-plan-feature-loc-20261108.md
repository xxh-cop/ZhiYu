### 幕一 · 开场定位（0:50）

**做什么**：学生端登录页 `/#/pages/login/index` → 勾选隐私协议 → `demo_zhiyu_2026` 登录 → 首页 `/pages/home/index`。

**说什么**（一句主张 + 事实）：
- 主张：「织愈用一针一线缝补青春的焦虑——但我们的第一行代码写的是边界：这是陪伴，不是诊疗。」

**风险点**：dev server 或后端没起；隐私勾选框漏点导致按钮不可点（演示者自己卡自己）。

**兜底**：截图 `flow-01-emotion/01-home.png`、`02-chat-opening.png`；一句话带过：「登录是标准 JWT，不占用大家时间，直接看主页。」

### 幕二 · 学生端主线（4:40）

#### 2a 情绪倾听（1:20）——回答「AI 怎么守住边界」

**做什么**：`/pages/emotion/chat` 发送「最近 ddl 压得喘不过气，晚上睡不着」→ 等 SSE 流式回复 → 手指气泡与页底免责声明。

**说什么**：
- 主张：「AI 会共情，但永远不越界做诊断。」
- 事实①：句级真流式，不是整段转圈（历史压测：20 并发首 chunk P95 1818ms，2026-11-02）；
- 事实②：输入先过安全过滤再调模型——高危词命中直接走危机流程，**不调用任何模型**（顺序有钉子测试守着，见 §二·2）；
- 事实③：每次调用落审计与 trace，谁服务、多快、成败可复查。

**风险点**：云端首字慢（>5s 无字会显得像卡死）；演示语料偶发触发软档类回复。

**兜底**：截图 `03-chat-user-sent.png` / `04-chat-ai-reply.png`（DeepSeek 当次真实生成留档）；话术：「真实生成，几秒等待是它的真实代价。」**不现场输入危机词**——危机流程用 `/pages/crisis/index` 页面 + 截图 `06-crisis-entry.png` 口述。

#### 2c 手作推荐 + 创作会话（1:40）——回答「为什么是手作」

**做什么**：`/pages/craft/recommend`（AI 推荐理由）→ `/pages/craft/detail?id=940001`（材料安全提示与原创声明）→ `/pages/craft/session`（分步引导）。

**说什么**：

**风险点**：推荐理由生成变慢；现场等不出心流/呼吸（要 5 分钟无操作）。

**兜底**：截图 `flow-02-craft/01~05`；心流与呼吸**只口述 + 指配置键**，不现场等。

## 二、创新点（每条可指到代码/机制/数据，标注证据强度）

> 证据强度三档：**已实测**（有真实运行/评测数字）、**有代码但未实测**（实现完整但缺真实环境证据）、**设计阶段**。
> 站不住的方向（RAG 本地文件检索、语音真实通话、「数据不出校园」、心流疗效）**主动不写**，原因见文末。

### 1. 按能力分档的模型路由：云主用、本地兜底、审核类硬禁本地顶替 —— **已实测**

- **机制**：`LlmClientRegistry` 持有 cloud/local 双 client，`ModelRouter` 按能力级策略表路由（`chat/recommend/message → local` 兜底，`moderation → none`）；`ProviderRoutingValidator` 启动期 fail-fast + `AiClient` 运行期校验 + 契约测试三层防死「审核被本地顶替」；`CloudErrorClassifier` 窄匹配区分 401/403/429/超时。
- **与常见做法的差异**：多数项目是全局一个 key 一个端点，云挂了要么报错、要么全局降级（包括审核这类高判定质量能力一起降）。我们按能力分档——陪伴能力可降，审核能力宁可说「暂不可用」也不降质。
- **证据**：2026-11-08 彩排实测：401/死端点注入下对话/推荐/寄语全兜底（双段 trace：云 104–393ms FALLBACK → 本地 6.4–7.0s OK）；审核建议本地 41ms 明确返回不可用；`features/75-provider-fallback.feature`、`76-ai-model-routing.feature`；管理端「模型路由」只读面板。
- 代码指针：[LlmClientRegistry.java](file:///d:/develop/Zhi_Yu/zhiyu-backend/src/main/java/com/zhiyu/ai/client/LlmClientRegistry.java)、[ProviderRoutingValidator.java](file:///d:/develop/Zhi_Yu/zhiyu-backend/src/main/java/com/zhiyu/ai/routing/ProviderRoutingValidator.java)、[CloudErrorClassifier.java](file:///d:/develop/Zhi_Yu/zhiyu-backend/src/main/java/com/zhiyu/ai/resilience/CloudErrorClassifier.java)。

### 2. 危机识别与 LLM 解耦的规则短路 —— **已实测**

- **机制**：`HighRiskLexicon`（39 词，按等级分组）+ `KeywordContentSafetyFilter` 在 **provider 选取与任何 LLM 调用之前**短路；命中即 BLOCK → 关怀话术 + 热线 + `care_reminder` 脱敏摘要落库（不存原文、加密存储）；`CrisisOrderPinTest`（2026-11-08）用真实词库在两条对话路径上钉死「真词命中 → 零模型调用」的顺序。
- **与常见做法的差异**：常见做法是把安全判定也交给大模型（同一条链路），模型挂了安全也挂。我们把最不能失败的那一层做成纯本地规则——断网、熔断、key 失效都不影响危机识别。
- **证据**：顺序钉子测试 2 条路径（2026-11-08）；审核 AI 层 180 次真实调用高危漏放率 0%（moderation-gate-eval，2026-11-05/07）；词库兜底覆盖率约 14%（90/105 正例靠 AI 层）如实披露，不夸大词库。
- 代码指针：[HighRiskLexicon.java](file:///d:/develop/Zhi_Yu/zhiyu-backend/src/main/java/com/zhiyu/ai/safety/HighRiskLexicon.java)、[CrisisOrderPinTest.java](file:///d:/develop/Zhi_Yu/zhiyu-backend/src/test/java/com/zhiyu/ai/CrisisOrderPinTest.java)。

### 3. 对照实验驱动的审核软档处置链（窄门 + 分层抽检 + 位次降权 + 影子观测） —— **已实测（评测）/ 生产流量未开**

- **机制**：第三档 `SOFT_CONCERN` 给「良性但拿不准」的情绪表达出路；窄门唯一放行条件 `narrative=self_disclosure` 由服务端代码终裁；`moderation_soft_review` 台账承载分层抽检（mandatory 三层全覆盖 + 随机 1/3）、位次降权（N=20，软档永不进前两屏）、24h SLA 保守默认、申诉即升级；影子模式双开关（`local-demo-mode` + `demo-providers`）保证演示数据不进生产口径。
- **与常见做法的差异**：常见审核是二元（过/不过）+ 调 prompt 靠感觉。我们的阈值变更必须过三臂回归门槛（红线集非劣 + 良性拦截 ≤5% + hard_gate 8/8 零容忍），数字由冻结回归集复跑产出，不靠拍脑袋。
- **证据**：962 次两臂对照基线（2026-11-07）：良性拦截 46.08%→2.94%、L3 漏放 7.65%→3.24%、干净放行 50.98%→67.65%、软档落档 22.55%（95% Wilson [15.52, 31.57]）；处置链已实现（全量测试 965 通过，2026-11-07），`features/73/74`；**生产流量未开**（G1 影子观测未跑真实流量，默认 `enabled=false`）。
- 代码指针：[SoftTierRecordService.java](file:///d:/develop/Zhi_Yu/zhiyu-backend/src/main/java/com/zhiyu/modules/work/service/SoftTierRecordService.java)、[moderation-soft-tier-disposition-chain-20261107.md](file:///d:/develop/Zhi_Yu/docs/moderation-soft-tier-disposition-chain-20261107.md)。

### 4. 情绪—手作闭环的心流度量与自评校准 —— **有代码但未实测（大样本）**

- **机制**：`FlowDetectionService` 阈值全配置化（心流 300s 无切换 / 焦躁同步骤 3 次停留 → 4s/6s 呼吸）；自评校准（1–7 李克特，抽样率 0.2，Spearman ρ 阈值 0.3、minSamples 30，样本不足自动降级为「专注停留占比」口径）；管理端专注度量看板页脚常驻「engagement ≠ 疗效」。
- **与常见做法的差异**：常见做法是把「在线时长」包装成「疗愈效果」。我们把行为信号（心流）与主观感受（自评）做成双轨，用统计相关而非疗效断言；样本不够时，看板标题如实降级显示。
- **证据**：单测与真库冒烟通过（2026-11-05，手算精确吻合）；真实样本仅 1 个活跃用户、3 个纳入会话（台账 K4）——**统计行为未经大样本检验，如实标注**。

### 5. 隐私工程：应用层加密 + 35 表注销级联 + 16 类导出 —— **历史验证**

- **机制**：对话/便签 AES-256-GCM 应用层加密（密钥只存服务端，缺失即启动失败）；注销级联覆盖 35 表（`AccountEraseCoverageTest` 守门，新表漏接入测试即红）；16 类个人数据导出（每批 100 条游标分页、服务端解密交付、禁响应缓存）；媒体签名 URL + 撤回后重鉴权（旧签名即时失效）。设计例外如实登记：`care_reminder.summary` 存脱敏文本不加密、`work.message`（AI 寄语）明文属设计决策。
- **与常见做法的差异**：常见做法靠数据库透明加密，应用日志与导出链路漏明文；我们在应用层加密，导出即解密交付，撤回授权立即生效。
- **证据**：历史验证（2026-10-20 集中收尾 419 项回归、2026-11-05 台账复核），本轮未重跑。

### 6. 工程治理闸口：契约先行 + 幂等迁移 + 结构兼容检查 + 场景守门 —— **已实测（每次构建/测试执行）**

- **机制**：`openapi/openapi.yaml`（5,258 行单文件契约）改接口先改 YAML；`sql/migrations/` 幂等增量脚本（information_schema 检查，可重复执行）+ 双份 schema-h2 + `SchemaCompatibilityCheck` 启动 fail-fast（缺列拒绝启动）；96 个 Gherkin `.feature` 场景；JWT/字段加密密钥 fail-fast；WXSS 产物方言闸口（`check-wxss-wildcard.js` 扫构建产物）。
- **与常见做法的差异**：多数项目契约与迁移靠 review 自觉。我们把闸口做成机器执行：缺列启动失败、密钥过短启动失败、方言选择器扫产物。
- **证据**：每次启动/测试/构建实际执行（2026-11-05 冒烟实例 SchemaCompatibilityCheck 通过）；本轮 LOC 与静态核对再次确认（见 §五）。

**主动不写的方向与原因**：RAG 检索（本地文件存储，属常规实现，不冒充 Milvus/Chroma）；千问语音（未真实验收）；「数据不出校园」（云模型模式下不成立）；心流「疗效」（无 4–8 周配对随访证据，我们不宣称）。

## 三、社会意义（具体到人、到事、到条件）

### 1. 服务谁

高校在校学生。单校体量 1–3 万人；全国普通高等学校三千余所、在校生数千万（公开统计口径）。直接目标用户是**够不上心理咨询、又需要情绪出口**的中间人群，以及心理中心需要前置筛查线索的咨询师。项目当前定位：**校内试点**，不是公众产品。

### 2. 解决什么具体困难

| 具体困难（不是大词） | 织愈的对应机制 |
|---|---|
| 夜间、考前、假期咨询不在岗时的**倾诉空窗** | 7×24 情绪对话（SSE 流式）+ 云故障时本地兜底，主陪伴链不依赖单一云厂商 |
| 「够不上咨询又难受」的**中间地带** | 手作创作把情绪调节落到可完成的具体行动（推荐 → 分步引导 → 完成仪式），不是只聊不做 |
| **病耻感**阻碍求助 | 匿名发布、无诊断话术、「陪伴非诊疗」定位降低心理门槛；危机入口不要求用户先承认「我有病」 |
| 心理中心**筛查靠等上门** | 危机事件落 `care_reminder` 脱敏摘要（不存原文），咨询师在授权范围内认领跟进——把「等求助」变成「有线索」 |

### 3. 为什么是「非遗 + 心理陪伴」，而不是别的形式

- **手作的机制适配情绪调节**：重复节律动作带来专注（心流），完成一件实物带来自我效能感，材料与步骤提供非语言的表达通道——这比纯冥想 App 多了产出物与可分享的社交货币，比纯咨询预约门槛低一个数量级。
- **非遗的内容适配校园场景**：绳结、绒花、竹编、盘扣等项目材料便宜、场地要求低、文化亲近感强，且天然连接传承人资源（课程、工作坊）——这是通用手工教程没有的内容纵深与校园合作抓手。
- **如实标注边界**：手作与情绪的关联是「陪伴与引导」设计假设，不是疗效结论；仓库内所有页面守「不诊断」红线，度量看板明示「engagement ≠ 疗效」。

### 4. 可复制性（别的学校/机构拿去用，需要什么）

| 条件 | 说明 |
|---|---|
| 工程 | MySQL 8 + Redis（可选）+ 一个云 LLM key（或本机 Ollama 兜底）；代码即部署物，配置全环境变量化 |
| 内容 | 种子手作项目可替换为本地非遗资源；传承人角色体系现成 |
