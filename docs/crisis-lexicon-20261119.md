## 3. 改动一：「求救信号」不能整词掩码

### 3.1 机制

- **删除**第一轮的无条件掩码项 `求救信号`。
- 在 `high-risk-benign.txt` 新增 `# @context` 段，格式为：

```
弱信号|良性语境词1,良性语境词2,...
```

当前唯一一条：

```
求救信号|演练,演习,预案,科普,教学,讲座,培训,课堂,课程,课件,教材,课本,教程,电影,影视,剧情,剧集,小说,漫画,游戏,动画,设备,仪器,装置,警报器,警报,信号灯,信号弹
```

语义：只有归一化文本**同时含有**「求救信号」和任一良性语境词时，才把「求救信号」替换为占位符；否则保留，让底层 1 档关键词「求救」照常命中。

- 另加 4 条**无条件**设备复合词掩码：`求救信号器`、`求救信号灯`、`求救信号弹`、`求救信号枪`（设备名本身不含语境词也能被正确中性化）。

### 3.2 为什么能同时满足两头

- **正常语境**（演练、科普、影视、设备、警报器）在中文表达里通常会显式出现这些语境词；命中语境词才掩码，因此这些句子不触发。
- **真实求助**通常不会同时出现「演练/电影/设备」这类词；不满足门控条件，词保留，命中「求救」1 档。
- 与「整词掩码」相比，门控把**是否中性化**从「词形」提升到「词形 + 同句语境」，避免一刀切漏放。
- 设备类另有固定复合词兜底，不依赖语境词是否出现。

### 3.3 成对测试（真实执行，全部通过）

真实求助命中（`HighRiskLexiconTest#realCryForHelpSignalHits` + 集成用例）：

1. 这是我的求救信号 → 命中「求救」1 档
2. 我在发求救信号，有人能看到吗 → 命中
3. 求你看到我的求救信号 → 命中
4. 集成：`checkInput("这是我的求救信号")` → `BLOCK` + `care_reminder.risk_level = 1`

正常语境不命中（`HighRiskLexiconTest#benignSignalContextsDoNotHit` + 集成用例）：

1. 消防演练中，大家练习如何发出求救信号 → PASS
2. 科普讲座介绍了求救信号的几种发送方式 → PASS
3. 电影里的主角靠求救信号等到了救援 → PASS
4. 他按下了求救信号器 → PASS
5. 警报器发出的声音就像求救信号 → PASS

## 4. 改动二：「永别」不能单独判 2 档

### 4.1 选择：降为 1 档 + 终局宾语短语保留 2 档

- 「永别」从 2 档组移入 1 档组（关注）。
- 2 档新增 8 条带终局宾语的固定短语：
  `永别这个世界`、`永别了这个世界`、`永别了，这个世界`、`永别了,这个世界`、
  `和这个世界永别`、`跟这个世界永别`、`向这个世界永别`、`与这个世界永别`。
- 最长匹配保证：「和这个世界永别」命中 7 字短语（2 档），「和焦虑永别」只命中「永别」（1 档）。

### 4.2 为什么选「降 1 档 + 短语」而不是只要求宾语

- 只保留宾语短语、完全删除「永别」，会漏掉「永别了」「永别，大家」这类真实终局表达；降为 1 档仍进入关怀通道，只是不按紧急档升级。
- 反过来，把「永别」单独留 2 档会把「和焦虑永别」「跟失眠永别」这类康复叙事按高危处理，与产品目标冲突。
- 两条措施叠加后：**有终局宾语 → 2 档；只有「永别」→ 1 档**，同时保住召回与精度。

> 口径说明：本系统**任何档命中都会 `BLOCK` 并触发关怀提醒**，等级只影响 `care_reminder.risk_level` / 危机摘要紧急度。因此「不进 2 档」的实际含义是 `risk_level = 1`，不是「不阻断」。

### 4.3 测试钉子

- `bareFarewellIsOnlyLevel1`：`永别`、`永别了`、`和焦虑永别`、`跟失眠永别了`、`和过去永别` 全部命中且等级 = 1。
- 集成：`checkInput("我想和焦虑永别，重新开始")` → `BLOCK` + `risk_level = 1`（不是 2）。
- `farewellExpressionsHit`：15 条终局告别表达全部命中且等级 = 2。

## 5. 匹配逻辑与不变量

1. `containsRisk` 统一委托 `firstMatch`，两条路径口径一致。
2. `firstMatch` 先做中性化（无条件项 + 语境门控项），再取**最长命中词**；同长度取更高档，避免 `HashSet` 遍历顺序影响定级。
3. 中性化用 `\u0000` 占位而非删除，避免前后文拼接出新命中。
4. **加载期 fail-fast**：每条中性化项/门控项必须至少包含一个关键词，且所含关键词全部为 1 档；否则启动失败（防止误把「遗书」写进掩码表）。
5. 测试 `benignPhrasesNeverMaskStrongerSignals` 对无条件项与门控项同时复核同一不变量。
6. 危机识别顺序未变：真实词库 + 真实过滤器的 `CrisisOrderPinTest` 两条路径仍先于任何 provider / LLM。

## 7. 仍未覆盖与存疑项

1. **否定/反转语境会误掩**：如「这不是演练，这是我的求救信号」「我像电影里那样发出求救信号」会上文含良性语境词而被掩码，属于已知漏放边界；本轮未做否定检测。
2. **只有「求救」没有「求救信号」的科普句**（如「科普：落水如何求救」）不在门控范围，仍按 1 档命中；门控只针对「求救信号」这一复合词。
3. **单独「永别」只到 1 档**：「永别了，大家」这类无「世界」宾语的终局表达只进关注档，不按 2 档升级。
4. **带标点变体仍依赖显式词条**：「永别了，这个世界」已收录全角/半角逗号两种写法；其它标点（如「永别——这个世界」）未覆盖。
5. **其它告别词族**：「再见」「道别」「永别了，我的家人」等未纳入；泛化「告别」仍刻意不收（毕业/离职/康复叙事不可枚举）。
6. **掩码的召回代价**：语境门控是「同句出现良性语境词」的粗条件，真实求助句若恰好提到电影/演练会被漏放，需在后续词库评审中复核。
7. **软档抽样副作用**：`SoftTierRecordService` 复用同一词库做审核抽样分层（功能默认关闭）。新增「永别 / 求救」等词会让相关内容更容易进入 `mandatory_lexicon` 层；本次未改该逻辑，仅记录影响面。
8. **共现规则仍不实施**：多词槽规则（手段 × 时间 × 告别等）继续停留在 `docs/highrisk-cooccurrence-design-20261105.md` 的设计状态，未接入判定。
