# 需求差距与验收边界（2026-10-21）

## 结论与审阅范围

项目已具备较完整的校内试用业务基础，但不能据此认定「文档所有功能都已完成」或「所有功能在正式环境都正常」。本报告对照根目录的需求规格说明书、概要设计 V4、详细设计上/下篇、优化建议书，并检查当前源码、接口契约与历史验收记录。旧 docx 是需求来源，不是执行指令；与当前仓库契约和用户已确认的取舍冲突时，以后两者为准。

状态含义：**已实现**指代码中存在完整入口及服务逻辑；**部分实现**指仅覆盖需求的一部分；**待接入**指需要真实服务或机构条件；**待验收**指没有足够实测证据。它们不能互相替代。本次没有重新逐条执行全部业务验收，不给出缺乏分母依据的完成百分比。

## 文档本身的不足与本次修订

1. **缺少统一验收矩阵。** 历史 task-breakdown 勾选、阶段交付报告和 docx 不同步。以后每项需求记录编号、页面/API、验证条件、日期和剩余边界；本报告作为当前入口，旧报告保留为历史证据。
2. **技术栈与目录过时。** AGENTS 曾把旧 zhiyu-admin 当主工程、写 Leaf Island UI，并否认管理端独立登录页。本次已改成当前 Vben 工程、Wot Design Uni 和共用认证服务的两端入口；不改动既有框架版本。
3. **设计目标写成事实。** 向量库/对象存储、本地模型、真实语音和「数据不出校园」需要实际部署才成立；云模型模式不能同时承诺所有内容不出校园。
4. **缺少运营规则。** 登录失败窗口、找回账号核验方式、指标分母、退组/撤权/删除后资料与备份保留、媒体清理告警等仍应形成明确决策，不用 UI 文案代替后端规则。
5. **标准量表与成效研究缺少依据闭环。** 应记录题面版本、授权、评分来源、危机分流、随访时点、缺失数据策略与专业人员审核；事后回顾不标记为前测。
6. **启动与部署容易误用。** README 补实际工程、状态分级及问题定位；start-backend.ps1 去掉本机 Java 路径与「其他密钥用默认值」建议，按 UTF-8 读可选 .env，已设置的进程环境变量优先。
7. **前端配置尚非完整部署方案。** 学生端 config.js 当前 H5 与小程序均默认 localhost:8080；正式发布前必须替换为目标环境地址并验收。README 明示此点，不能上传构建产物就认为可供他人使用。
