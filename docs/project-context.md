# 项目上下文（Project Context）

> 给人读，也给 AI Agent 检索。说明「我们为什么这样设计」，避免后续开发反复推翻既定决策。

## 1. 业务背景

- 目标用户：在校大学生，面对学业/人际/未来压力，情绪低落与焦虑高发。
- 痛点：专业心理咨询资源有限、主动求助意愿低；传统「心理测评」类应用有医疗化压力，学生不敢用。
- 解法：用非遗手作的**重复性、节奏感、即时成就感**做表达性艺术疗愈，叠加 AI 低门槛陪伴，绕开「我是不是有病」的心理门槛。

## 2. 关键产品决策（已定，勿轻易推翻）

| 决策 | 选择 | 理由 |
|---|---|---|
| 产品定位 | 陪伴/引导，**非诊断** | 规避医疗合规风险，降低用户使用门槛 |
| 端形态 | 学生端 UniApp 小程序+H5；管理端 Vue3 Web | 校园扫码即用 + 评委浏览器演示；一套 Vue 代码两端 |
| AI 对话 | SSE 流式逐字输出 | 降低等待焦虑，符合陪伴体感 |
| 推荐策略 | **规则层 + LLM 层混合**，不纯靠大模型 | 可控、降幻觉、可解释；LLM 只负责生成理由和引导语 |
| 心流判断 | 基于行为信号（时长/步骤/呼吸响应），不上传感器 | 小程序/H5 无传感器权限，门槛低 |
| 危机干预 | AI 不做结论，转人工/热线 | 法律与伦理红线 |
| 数据部署 | 支持云端 + 本地化两种；本地模式切 Ollama+Qwen | 满足「数据不出校园」的合规诉求 |

## 3. 架构约束

- **后端单体优先**：学生项目不微服务；按模块分包（见 AGENTS.md §2），预留拆分边界。
- **AI 调用必须走门面**：业务代码不直接碰 OpenAI/讯飞 SDK，统一经 `AiClient`，便于换模型、加熔断、做审计。
- **敏感数据加密在服务端**：前端永远只拿明文；密钥不进 Git、不下发浏览器。
- **接口前后端分离**：REST + JWT；学生端与管理端共用同一后端，靠角色分流。

## 4. 技术选型理由

| 选型 | 为什么是它 |
|---|---|
| Spring Boot 3.2 | 团队已有经验；Spring AI 原生集成 LLM，生态成熟 |
| MyBatis-Plus | 单表 CRUD 快，逻辑删除/自动填充开箱即用 |
| UniApp | 与 Vue 技术栈一致；uni-sse 解决小程序 SSE 痛点；一套代码双端 |
| Element Plus | 管理端快速搭后台，组件全 |
| Milvus / Chroma | 非遗知识库 RAG；Chroma 适合本地轻量，Milvus 适合云端规模化 |
| Redis | 会话缓存、熔断计数、限流 |

## 5. 已知边界与不做的事

- **不做**：心理量表自动诊断、抑郁/焦虑症标签、面向 C 端的商业化付费。
- **不做**：实时音视频心理咨询（这是专业平台的事）。
- **不做**：医生/医院对接、电子病历。
- **一期不做**：互助小组实时聊天、传承人直播、付费课程。

## 6. 合规红线

- 《个人信息保护法》：敏感心理数据属敏感个人信息，须**单独同意**、可撤回、可导出/删除。
- 不采集身份证、通讯录、精确位置。
- 首次进入弹「不替代专业心理咨询」声明。
- 高危识别后必须展示心理中心电话与援助热线，由用户自主选择是否求助。

## 7. 验收口径

- 高优先级 FR 全部可用（见需求规格说明书第 3 章）。
- 学生端能在微信小程序与 H5 完整跑通一次疗愈闭环。
- 危机干预流程可走通，AI 输出安全过滤生效。
- 试点：学校心理中心 4 周、30–50 名学生，前后情绪自评 + 满意度问卷。
