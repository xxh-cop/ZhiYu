# 导出审计设计（N2，2026-11-04）

> 目的：为「评论导出重新开放」做审计准备，并把已在用的 users/works 导出纳入留痕。
> 四件必须齐：**操作留痕、权限分离、脱敏/水印、批量告警**。缺一件，评论导出就不开放。
> 本文档 = 设计 + 本次已实现范围（§5）+ 评论导出开放条件（§6）。

## 1. 操作留痕（已实现）

导出动作登记到 `admin_export_log`（只追加、不更新、不删除，同 ai_audit_log 审计语义）：

| 字段 | 说明 |
|---|---|
| id | 雪花主键（应用侧 ASSIGN_ID） |
| actor_id / actor_role | 谁导出的（管理员 id 与当时角色） |
| target_type | 导出对象：users / works / comments |
| filter_summary | 筛选条件**脱敏摘要**（≤500 字；不存用户输入原文以外的敏感内容） |
| field_list | 导出字段列表（逗号分隔；**禁止** password/secret/加密列进入该清单，服务端校验拒绝） |
| record_count | 导出条数（告警判定的输入） |
| purpose | 导出用途（≤200 字，必填——没有理由不许导出） |
| batch_no | 导出批次号（雪花，字符串下发；文件名与文件头引用它） |
| alert_flag | 0 正常 / 1 超阈值告警（见 §4） |
| create_time | 留痕时间 |

接口：`POST /api/admin/export-logs`（登记，返回 batchNo 与建议文件名）；
`GET /api/admin/export-logs`（审计自查，分页只读，不含业务原文）。

## 2. 权限分离（矩阵）

| 操作 | role=0 学生 | role=1 传承人 | role=2 咨询师 | role=3 管理员 |
|---|---|---|---|---|
| 导出 users（账号清单） | 否 | 否 | 否 | **可** |
| 导出 works（作品清单） | 否 | 否 | 否 | **可** |
| 导出 comments（评论） | 否 | 否 | 否 | **暂不开放**（条件见 §6） |
| 登记/查询导出留痕 | 否 | 否 | 否 | **可** |

二次授权：评论导出开放时，必须要求**导出用途必填 + 单次导出独立留痕**；
更高敏场景（含联系方式字段）建议未来加「二次确认」交互，本期不做。

## 3. 脱敏与水印

- **字段级**：`field_list` 服务端黑名单校验——出现 `password`、`secret`、`key`、
  `cipher`、`identity_cipher`、`token` 直接 1001 拒绝（加密列永不出库）。
- **内容级**：评论内容属于用户表达，开放导出时默认**不导出 content 全文**；
  需要全文时必须在 purpose 中写明用途并单独留痕（开放条件之一）。
- **水印**：CSV 是纯文本，**不可行**（任何「不可见水印」都能被文本编辑器删除）。
  可行替代（已实现口径）：
  1. **文件名带批次**：`export-{batchNo}-{targetType}-{yyyyMMdd}.csv`，批次号可回溯到留痕记录；
  2. **文件头注明**：导出文件首行写
     `# exported_by=<actorId> exported_at=<ISO时间> batch=<batchNo> purpose=<用途>`，
     泄露后可凭批次定位到留痕记录（威慑与追责，不是防泄露）。

## 4. 批量告警（已实现）

- 阈值：`zhiyu.export.alert-threshold`，默认 **5000** 条/次（可配置）。
- 触发后：`alert_flag=1` 落库 + 服务端 `log.warn`（含 actor/batch/count，**不含数据原文**）；
  登记接口响应 `alert=true`，前端应给出显式提示。
- 后续可接 ops/health 或通知系统推送管理端（当前不在范围，不虚构）。

## 6. 评论导出的开放条件（四件齐备的验收标准）

同时满足才允许开放：

1. **留痕**：每一次评论导出都先登记 `admin_export_log`（本接口已具备）。
2. **权限分离**：仅 role=3；purpose 必填；含 content 全文的导出必须在用途中明确说明（§3）。
3. **脱敏/水印**：导出字段黑名单生效（已实现）+ 文件名带批次 + 文件头注明（§3）。
4. **批量告警**：超阈值告警可送达（当前为日志 + 响应标记；接入管理端告警条后视为齐备）。
