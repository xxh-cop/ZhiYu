## 1. 已确认的范围与取舍

用户要求一并完成此前讨论的非遗 I0–I4、学生 UI S1–S5；保留此前已选的倾听小结和 AI 治理，放在非遗与核心体验之后推进。

### 纳入

1. 有出处的技艺档案、原创教学纹样、色板、来源与授权管理。
2. 学生纹样馆、纹样详情、工艺档案、绘色与临摹接续、作品文化卡。
3. 图增强知识检索、引用可追溯与评测；受工艺规则约束的 AI 纹样共创。
4. 首页与开始页**保持原有信息架构和既有入口**；首页仅新增一个“非遗纹样馆”入口，不重排、不删减原功能。核心页面只做增量的状态、可访问性与视觉一致性优化，另加适量工艺动效。
5. 成长回看、作品草稿、环境声与偏好设置的体验收口。
6. 地域探索与节令策展入口，内容规模以真实可核实条目为限。
7. 本人可编辑的倾听小结、管理员只读 AI 治理、真实模型联调。
8. 跨端构建、浏览器验收、内容审阅、隔离演示数据与答辩材料更新。

### 不因本次批准而引入

- 新吉祥物、logo 重绘、第二套 UI 库、框架升级。
- Neo4j、独立 Python RAG 服务、任意模型 SVG/HTML 执行、模型训练。
- 核心链路中的 WebAR、3D Gaussian Splatting、Rive 或数字人。
- 全站性能工程、微服务拆分、生产部署、付费素材购买。
- 自动上传私人对话、作品图像或密钥到第三方工具。

首选现有技术的最小扩展；开源项目先用于研究交互与结构，未经许可、版本和跨端核实不复制资产或引入依赖。

### 3.1 首批四个正式项目

| 正式项目 | 编号 / 公布信息 | 地域 | 内容呈现方向 |
| --- | --- | --- | --- |
| 民间绣活（夏布绣） | Ⅶ-77；2014 年第四批 | 江西新余 | 夏布基底、针线关系、工序与原创练习 |
| 竹编（瑞昌竹编） | Ⅶ-51；2008 年第二批扩展项目 | 江西瑞昌 | 经纬交错、材料与结构示意 |
| 剪纸（瑞昌剪纸） | Ⅶ-16；2008 年第二批扩展项目 | 江西瑞昌 | 剪刻、正负空间与连结示意 |
| 景德镇手工制瓷技艺 | Ⅷ-7；2006 年第一批 | 江西景德镇 | 制瓷工序、器物装饰与材料认识 |

不把笼统的“赣绣”直接当成已核实的名录名称；也不把四个项目硬凑成四个城市。既有普通手作仍可保留，但与名录项目分层标识。

### 3.2 来源、原创与授权的三层标识

- **传统资料**：可核实事实的原创转述，标注来源机构、标题、链接、访问日期和支撑的具体事实。
- **原创教学再设计**：由本项目制作的纹样和工序示意，说明借鉴了什么结构、作了什么简化；不是文物复刻、官方教材或传统纹样真迹。
- **合成演示记录**：演示账号、作品与人物资料明确标注为合成；不展示伪造资质、认证、口述史和从艺年限。

历史年代、寓意、名录级别和传承关系不能由模型自由补全。公开网页未明示照片再利用许可时，不下载入库；AI 生图也不能自动取得“传统原作”身份。

首批目标为每个项目六份原创教学构图，共二十四份；每份分别检查来源关系、视觉差异、可操作性和标注。不能仅变更随机数或重复密度来凑数量。

### 3.3 内容不是皮肤

每个项目至少有：材料与工具、工序拆解、入门练习、与传统完整工艺的区别、来源。短时数字绘色/纸上模拟不得标成已完成真实刺绣、竹编或烧制。

- 竹编危险的劈篾等工序只介绍，不向初学者提供无指导的操作任务。
- 制瓷烧制由有条件的工坊完成；数字配色或纸上装饰不能称为烧制成品。
- 纹样与配色不作心理诊断，也不建立“某纹样治疗某疾病”的关系。
- 传统寓意只有在具体来源支持时展示；否则标注本次原创设计意图。

## 4. 产品主线与页面职责

主线：了解一门技艺 → 选择材料与时间 → 选择/共创纹样 → 跟着做 → 记录感受 → 保存或分享作品文化卡。

### 首页与开始页（用户修订：不重排）

- **首页保持现有布局、内容顺序和全部原入口**：情绪签到、小织、音乐、练习、推荐、每日一句、探索链接等均保留。
- 仅在首页现有的 DISCOVER/探索区域新增一个“非遗纹样馆”入口卡/链接，不改变原有卡片布局；入口文案明确“看纹样、读工艺、试着配色”。
- **开始页保持原样**，不合并入口、不删减聊天/手作/正念/音乐等既有功能。
- 保留现有五个 Tab 和既有业务入口；不更改分享返回、登录跳转或原页面路由。
- 样板中的首页设计只作视觉参考，不替换生产首页；纹样馆/详情/创作台样板用于新增页面与绘色增量。

### 纹样馆与工艺档案

- 馆页：技艺、结构、难度筛选；清晰区分传统资料与原创教学图案。
- 详情：大图、结构拆解、材料感配色、相关工序、来源与授权、“使用这个图案”。
- 传承人现有主页承接关联项目、经过核实的工艺资料与作品；缺少授权口述史/照片时不生成假内容。
- 地域探索以三座城市和四个项目为首批，提供可访问的列表。示意图明确不是测绘地图；不以外部地图服务作为进入内容的必需条件。
- 节令策展展示人工维护的主题与适用时间；不伪造节气精确时刻，也不把现代教学活动说成当地传统习俗。

### 创作、发布与成长

- 项目详情先解释材料、时间、准备与文化来源；创作页保留大号主要动作和可恢复进度。
- 完成仪式采用一次性的展开/针脚收束反馈，可跳过、可减少动效。
- 回顾可保存为本人记录，也可经本人确认带入作品故事；私人回顾不放进 URL 查询串，不自动发布。
- 发布保留三步流程和预览；优化标签、可见范围、匿名开关与重试反馈。
- 成长分为概览、日历、作品/感受记录；展示已保存的 AI 回顾正文，不只保存而无回看入口。
- 文化卡从已核实的技艺/纹样和本人作品生成，非认证证书；匿名与受众规则和作品一致。

## 5. 学生端视觉与组件契约

### 5.1 视觉方向

延续当前暖白、薄荷青、编辑式排版和小织；用材料细节增强非遗感，不用大面积红金或生硬仿古界面。

- 通用界面：可读的暖白背景、深色正文、有限层级的卡片和明显主动作。
- 工艺强调：夏布/针脚、竹编经纬、剪纸负空间、瓷白与装饰色；属于项目界面配色，不宣称历史标准色谱。
- 正念保留沉浸夜色，走统一语义 token；不强制所有页面采用同一背景。
- 正文/表单使用系统无衬线；少量章节标题可用系统衬线，不换 logo、不新增外部字体下载。
- 先以首页、纹样馆、创作页三个交互样板做浏览器自检与用户确认，再推广至全站。

### 5.2 不另建组件库

当前实际安装 Wot Design Uni 1.14.0，已读取本地 MIT LICENSE。复用已有 `AccessibleButton`、`AccessibleDialog`、`CraftCover`、`MediaVideo`，使用本地存在的 Wot form、radio、switch、segmented、popup、skeleton 等能力。

只在出现真实复用时抽取页面壳、区块标题、状态容器、工艺卡片与消息呈现；不为满足组件数量而封装所有 Wot 控件。按钮、弹层的键盘行为以编译后的 H5 DOM 验证。

### 5.3 Token 与动效

- 扩展现有 `theme.scss` 的语义层，不重设一套互不关联的尺寸系统。
- 页面 UI 不散落品牌色；作品颜料、原创纹样色板、测试夹具及必须静态配置的导航色不一刀切禁用。
- Canvas 所需颜色由共享配置解析，不能把 `var(...)` 当作跨端 Canvas 的通用支持保证。
- 状态动效优先 transform/opacity；针脚、展开只在相应动作发生时播放。
- 尊重现有系统偏好与应用内减少动效；呼吸 4 秒吸/6 秒呼和现有心流规则不改。
- 不新增循环背景动画，不将物理呼吸节拍替换成通用 150/250/400ms 过渡。

### 5.4 页面状态与功能核对

| 区域 | 必须完成 |
| --- | --- |
| 首页/开始 | 信息层级、继续创作、推荐失败保留已有内容、下一步可见 |
| 聊天 | 输入可见标签、等待/完成/失败/停止接收、重试、复制、建议问题、最新消息提示、危机支持可操作 |
| 推荐/项目 | 有来源的理由、时间/材料筛选、封面失败兜底、首屏与刷新状态区分 |
| 创作 | 步骤信息、进度保存/失败、暂停恢复、音频停止、离页行为、完成反馈 |
| 回顾/发布 | 可见字段标签、保存/发布忙碌、匿名/受众语义、已存在的预览与上传重试、草稿恢复 |
| 社区/作品/小组 | 分页失败保留页码与内容、评论保留输入、受众约束、失效链接恢复 |
| 成长/传承人/活动 | 信息分层、记录可回看、授权资料、无数据与加载失败不混淆 |

## 6. 后端边界与数据设计

维持 Spring Boot 模块化单体、MySQL、现有 JWT。新文化内容放入 `modules/heritage`，不复制现有项目、传承人、作品业务。

### 6.0 管理端内容维护 MVP（2026-10-29 实施）

在 4 门工艺/24 份纹样规模下，管理端维护先采用**整份目录 JSON 文档**方案，避免为此新增关系表：

- `GET/PUT/DELETE /api/admin/heritage/catalog` 仅 ROLE_3；读取返回 `{catalog, revision}`。
- 保存复用 `runtime_config` 的 `heritage_catalog` 键，带 revision 乐观锁（冲突 3001）、服务端目录校验（1001）和 `admin_operation_log`。
- 学生端 `GET /api/heritage/catalog` 优先读取该覆盖；无覆盖或覆盖损坏时回退 classpath 内置目录。
- 管理端页面支持编辑 4 门工艺、24 份纹样和 4 条来源，保存后学生端立即生效；“恢复内置目录”删除覆盖。
- 本 MVP **不含**新增/删除条目、草稿/发布/下架状态和关系表；这些在内容规模扩大后再迁移到规范化模型。不要把它描述成完整 CMS。

### 6.1 最小内容模型

| 数据 | 职责 |
| --- | --- |
| heritage_tradition | 正式名称、编号、地域、原创说明、工序、安全边界、发布状态与内容版本 |
| heritage_pattern | 所属技艺、名称、结构语法、参数约束、色板、原创标识、设计说明与版本 |
| heritage_source | 来源机构/标题/URL、访问日期、来源类型、事实摘要、素材许可状态 |
| heritage_relation | 白名单类型的已审核关系：技艺/纹样/来源/现有项目/传承人；不承载疗效关系 |
| work_culture_card | 与作品关联的文化设计快照、原始条目及版本；读取和分享复用作品权限 |
| work_draft | 本人一份主动保存的作品草稿，文本加密、媒体仅存本人授权引用 |

色板与参数约束归属纹样或技艺，首版不另建色板管理子系统。材料与工序使用受约束的数据结构，不建设无限制图数据库。

所有新业务表包含基础字段，使用雪花 ID；DDL 只写 `sql/schema.sql`，增量迁移、H2 和 SchemaCompatibilityCheck 同步。API ID 始终为字符串。

### 6.2 编辑、发布与读取

- 管理员维护公共文化内容，发布必须有可读来源、明确原创/许可标识以及有效参数。
- 传承人继续维护自己的项目和资料，不获得修改全局文化条目的权限；关联不能把普通账号自动升级为认证传承人。
- 内容采用草稿、发布、下架三态；修改已发布内容后重新审核，不能未审核直接进入 RAG。
- 学生只读取已发布内容；未发布、删除、失效来源不能通过图谱边、搜索或旧缓存泄漏。
- 关系校验两端存在、类型合法和发布范围；不允许客户端提交任意表名或模型片段。
- 公共静态教学资产与用户私有上传分开，文化卡不得绕过媒体授权。

### 6.3 草稿与文化卡

- 草稿通过明确的“保存草稿”操作写入，恢复已有草稿前提示；替换确认，不自动把隐私正文写入浏览器长期存储。
- 草稿图片/视频引用必须属于本人，签名 URL 不作持久标识；发布重新校验媒体和受众。
- 文化卡保存技艺、纹样版本、有限参数与引用快照，不含情绪原文或自动推导的心理标签。
- 作品私密、组内、下架、撤回、注销时沿用作品权限；公开文化卡入口不能借快照继续暴露已撤回作品。
- 草稿、小结和文化卡的本人导出、主动删除及注销处理同步已有 AccountLifecycle/导出机制。

## 7. 图增强 RAG 与可控共创

### 7.1 图增强检索

- 先组织已审核的技艺—材料—工序—纹样—来源关系，再对可公开的原创说明建立索引。
- 沿用当前向量召回与词面重排思路，增加有界关系扩展；不把“使用关系检索”宣传成部署了 LightRAG。
- 来源元数据包含稳定 ID、标题、URL、事实出处和内容版本；界面区分“检索参考资料”与经过核验的回答引用。
- 来源下架后查询立即过滤，即使旧向量尚在文件中也不能再用于回答。
- 索引增加语料/配置指纹；版本变化构建新快照后切换，不要求用户删除未知索引文件来刷新。
- 向量不可用时可展示结构化资料检索结果，但必须标注检索模式；不能把纯关键词检索称作向量模型已接入。
- 学生关系图首版使用小规模跨端 Canvas 加等价关系列表，不引用管理端 ECharts 依赖到学生端。

建立至少二十条人工确定的问题：事实查询、关系查询、资料不足、跨地域混淆、寓意无来源及提示词注入。分别记录检索命中、引用支持度、拒绝无依据回答与模型质量；不把引用链接存在当作答案正确。

### 7.2 AI 纹样共创

LLM 仅在用户选择的已发布模板、工艺和有限参数内生成三份变化方案；后端验证归属、字段白名单、结构类型、密度、对称范围、色板与最大图形复杂度。

- JSON 校验失败、越界或服务不可用：返回明确标注的内置方案。
- AI 不输出可执行 SVG/HTML；SVG/Canvas 均由本项目固定渲染器产生。
- 复用现有 lineart 场景边界并扩展契约，不并列保留两套互不一致的随机线稿系统。
- 用户能比较方案、改色/调整允许参数、撤销、导出、进入临摹，之后选择是否保存或发布。
- 模型的设计理由与文化事实分开；任何寓意解释必须链接已审核来源。
- AI 生成需要单独同意，默认不发送绘色画面、私人感受或聊天记录。

实现边界（2026-10-29）：首版已落地配色台内三变体比较、应用与恢复原纹样；完成四步后在页面内展示可复制的纹样文化卡。**不保存作品、不导出文件、不生成证书**；当前环境未配置真实模型，浏览器实测为内置变体降级，真实模型质量与小程序真机尚未验收。

## 8. 倾听小结与 AI 治理

### 倾听小结

本人已结束的倾听会话，用户主动同意后生成短小结；不自动覆盖现有 emotion_session.summary 的含义。生成与保存分开，允许编辑和放弃；保存复用本人加密成长记录的独立类型，并补齐回看、导出与删除。

只总结该会话实际内容；高危表达仍走现有支持流程，不生成诊断或心理疏导结论。AI 失败时提供固定的记录引导，不能用模板假装已经读懂会话。不会进入管理员/关怀视图。

### AI 治理

首版基于现有数据展示：安全审核事件数、场景分布、安全动作分布、标准化原因分类、最近事件和配置状态。只允许管理员读取，不返回用户 ID、原始输入输出或可能含隐私的自由文本原因。

明确不从审计事件推算“调用量/成功率/首字延迟”。配置存在、服务连通、合成输入实测通过是三种不同状态；真实联调指标单独报告。若未来需要调用遥测，另行设计，不在 UI 中编造。

### 真实模型联调门槛

执行前向用户确认本机凭据位置、可用模型/embedding 服务及是否允许用合成文本进行外部调用。不要求在聊天中粘贴 Key，不输出其内容，不将用户数据用于测试。已有聊天 Key 不代表 embedding、ASR/TTS 也可用。

当前安全审核策略不变；测量“请求至安全回复可见”的时间，不宣称未经实测的首 token 指标。

实现状态（2026-10-30）：倾听小结已落地为独立加密 `LISTENING_SUMMARY`，生成与保存分离，接入倾听记录、成长旅程、导出与删除；高危会话不生成/不保存，Mock 与模型失败明确标记 `generated=false`。AI 治理首版已提供管理员脱敏聚合页，只展示场景/动作/原因分类、最近事件元数据与配置状态，不做连通性或效果推断。真实模型、向量与语音联调仍待用户确认凭据后单独验收。

## 10. 验收与完成定义

### 内容

- 四门技艺正式名称、地域、编号可追溯；二十四份教学图案全部有原创与来源关系说明。
- 传承人资质、历史年代与寓意不依赖模型编造；媒体许可缺失时不复制。
- 数字模拟与真实工艺区分，免责声明和工具安全提示保留。

### 业务

- 已发布内容可查/筛选/查看/使用；未发布、下架与失效来源不可访问。
- 共创正常、越界、未同意、服务失败均有可操作结果，不吞掉原画面。
- 绘色、临摹、草稿、文化卡、回顾/小结可保存、恢复、导出/删除，受众与撤权一致。
- 管理端有内容维护入口，不仅静态 seed；统计口径准确。

### UI

- **首页布局、区块顺序和原有功能入口不变**；只新增一个非遗纹样馆入口，且不遮挡原内容。原聊天/推荐/创作/发布/社区/小组/成长/正念/活动/隐私等功能全部保留。
- H5 320/375/768/1280 下无页面级横向溢出；关键动作不依赖仅可点击 view。
- 首屏加载、保留旧数据的刷新、错误重试、空态和禁用状态分别验证。
- 键盘焦点、弹层关闭/恢复、输入标签、200% 放大及减少动效可用。
- 正文对比度目标 4.5:1，较大文字及必要非文本控件目标 3:1；颜料色本身与UI文字规则分开。
- 浏览器测试覆盖黄金路径与错误路径，记录控制台错误；不以构建代替页面验收。
- 图片/录屏证据只含合成数据；截图进入 output/playwright，不提交真实资料。

### 工程

- 后端定向测试与编译；管理端测试/typecheck/build；学生端测试、H5 与微信小程序构建。
- 接口先更新 OpenAPI，新增行为补 happy/error Gherkin。
- 数据迁移先在隔离 MySQL 测试库备份验证首次及重复执行，同步H2与启动兼容检查。
- 不覆盖运行中后端 class；只管理本次启动的进程，不停止用户其他服务。
- 视觉基线先人工确认，再做截图差异检测；不把改错后的截图自动接受为新基线。
- 不以全部状态页使用一个组件、全站零十六进制或新增组件数量作为完成指标。

真机微信、真实外部服务、公开运营内容和生产环境单独列验证状态；若外部条件缺失，只能列为待验收，不勾选整体完成。
