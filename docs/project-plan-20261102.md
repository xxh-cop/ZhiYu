审查结论压缩为一句话：**功能闭环完整、AI 工程纪律好，但「演示版 → 试点版」之间隔着四道门槛。**

| 门槛 | 内容 | 本计划对应 |
|---|---|---|
| G1 账号与访问安全 | 登录失败限制、忘记密码找回缺失 | 主线一 T1.1 / T1.2 |

| G4 文档可信度 | 14 条文档与代码冲突 | 主线一 T1.0（最先做） |

  前端自有组件库（ListPage/FormDialog/PermissionButton）与 Vben+Element Plus 互斥。
- **scaffold-master 实际带来的是哪一层（本轮代码核查结论）**：
  已移植的是**视觉表面层**——珍珠玻璃令牌（`--zy-glass-*`）、环境光、掠光 `.zy-sheen`、

### 2.1 T1.3 技术拆解：句级安全缓冲真流式（A 方案，已定）

背景：现行 `AiClient.streamChat` 把全部 token 累积后才下发（AiClient.java L153-169），
EmotionController 单事件发全文（L112）。A 方案在**不降低输入侧安全强度的前提下**，
把输出侧从「整段终检后一次下发」改为「分句缓冲下发 + 完整终检可撤回」。

#### 2.1.1 分句边界与缓冲策略（后端）

- 在 AiClient 内新增 `SentenceSplitter`：按 `。！？；\n` 切句，逗号/顿号不切（避免碎句）；
  缓冲上限 80 字——超过即强制切段（防止模型输出长难句无限缓冲）。
- 时序：LLM token → 累积进句缓冲 → 句边界到达 → **句级安全检**（复用
  KeywordContentSafetyFilter 的词库+正则，输入为该句）→ 通过则立即 emit `chunk` 事件；
  命中则该句不进流，直接转 2.1.3 的中断流程。
- 首句特殊处理：首句缓冲上限收紧到 40 字或首个标点，保证首字时间。

#### 2.1.2 安全终检的补偿手段（窗口缩小的对价）

- **双层防线**：句级检（逐句、即时）+ 完整终检（现有 checkOutput 全文 REWRITE/BLOCK 逻辑不变）。
- **撤回协议**：终检命中 REWRITE/BLOCK 时，向前端发 `revoke` 事件，携带安全替换文本
  （`SAFE_CHAT_REPLY` 或 rewrittenText）；前端整体替换最后一条 assistant 消息。
  已展示内容被替换属于可接受的温和回撤——陪伴场景下安全优先，且替换文本即干预话术。
- **命中高危立即中断**：句级检命中高危词库时，不再等后续 token，立即取消 LLM 流
  （取消 Reactor 订阅）、emit `revoke` + 关怀话术，`done` 携带 `crisis=true`。
- 输入侧逻辑（checkInput 前置、BLOCK 不调 LLM、写 care_reminder）**完全不动**。

#### 2.1.3 SSE 事件协议（新增与兼容）

| 事件 | data | 说明 |
|---|---|---|
| （无名，兼容）| 纯文本整段 | 旧格式，保留一个迭代周期供旧前端 |
| `chunk` | `{"text": "…"}` | 句级增量，按序到达 |
| `revoke` | `{"text": "…", "reason": "safety"}` | 撤回已发内容并整体替换 |
| `done` | `{"sessionId": n, "crisis": bool, "revoked": bool}` | 结束；revoked 标记供前端提示 |
| `error` | `{"code": n, "message": "…"}` | 现状不变 |

- openapi.yaml 的 `/api/emotion/chat` 响应文档同步登记（先改契约再改代码，AGENTS §6）。

#### 2.1.4 abort 与断线重连

- 前端 abort：沿用 sse.js 的 AbortController（H5）与 RequestTask.abort（小程序）。
- 断线重试：复用 companion 已确立的原则——同一请求可安全重发。重发前前端先查
  `GET /api/emotion/sessions/{id}` 最后一条消息：若该轮用户消息已存在且无 assistant 回复，
  直接重发 chat（后端按「最后一条 user 消息与本次 content 相同」去重，不重复 appendMessage）；
  若 assistant 已回复，直接读历史补全，不再调 LLM。
- 后端因此需要一个幂等判断：`appendMessage` 前比对会话最后一条消息内容，相同则跳过写入。

#### 2.1.5 前端 sse.js 两条路径

- H5（fetch/ReadableStream）：现按 `\n\n` 解析事件块，增加对 `event:` 行的分发
  （chunk/revoke/done/error）；chunk 直接 append，revoke 替换最后一条 assistant 消息全文。
- 小程序（wx.request enableChunked）：同一解析器复用；`wx.canIUse` 失败的 fallback
  （整包一次解析）天然兼容——整包里事件顺序完整，顺序回放即可。
- 打字光标：`chunk` 到达即显示文本，光标跟随；`done` 后收尾。不再需要假打字机。

#### 2.1.6 审计落库时机

- 输入审计：不变（checkInput 一条，含 sessionId）。
- 输出审计：**只在完整回复终检时写一条**（含是否 revoked、命中原因），
  句级检命中中断时也写一条（标记 interrupted），不逐句写——避免审计表膨胀。
- ai_audit_log 的 rawInput/aiOutput 加密方式不变。

#### 2.1.7 失败降级与「首字时间」测量

- 熔断/LLM 异常：流中断 → `error` 事件 → 前端降级为缓存图文（现有路径不变）；
  已发出的 chunk 保留，不回撤（与 revoke 区分：revoke 只用于安全场景）。
- **首字时间定义**：客户端发出 POST 到收到首个 `chunk` 的墙钟时间（performance.now 差值）。
- **测量方法**：① 单测：Mock LlmClient 按 50ms/token 注流，断言首 chunk 延迟 <500ms；
  ② 真实环境：dev 构建下前端记录最近 20 轮首字时间（localStorage），
  演示前用真实 key 跑 10 轮取 P95 写进验收记录；
  ③ 压测（T1.5）时把该指标纳入 k6 自定义度量。
- **达标线**：真实 key、demo 网络下 P95 ≤2s（NFR-02 原口径）。

#### 2.1.8 改动面清单

后端：AiClient（分句+句级检+revoke）、EmotionController（事件分发、幂等）、
测试（Splitter 单测、句级命中中断、终检撤回、幂等重发）。
前端：sse.js（事件分发）、stores/emotion.js（chunk/revoke 处理、断线补全）、chat.vue（光标）。
契约：openapi.yaml。文档：AGENTS §6、需求规格 NFR-02 口径不变（现在能真的达到了）。

## 3. 主线二 · UI 设计体系（重点）

原则：**先令牌与组件，后页面；页面重做以「解决具体问题」为单位，不以「换皮」为单位。功能只增不减。**

### 3.0 色彩与令牌治理（先于一切页面工作）

- **定一个品牌主色族**：建议以 logo 的 `#217E76` 为品牌主色，派生 50/100/500/600/700 五阶；
  学生端沿用其亮阶（接近现 `#2D9B8F` 的观感），管理端从 indigo 收敛到同一色族。
  暖金 `#EDBD77` 保留为唯一点缀。最终色值需用户确认（待拍板④）。
- **tokens.json 扩容**为单一事实源：color / spacing(4 基 8 档) / radius(卡片18·控件10) /
  shadow(单阴影) / motion(fast150·mid250·slow400 + 两条缓动，沿用 ui-guidelines §9) /
  typography(四级) / z-index。学生端 `theme.scss` 与管理端 `business.scss` 均由它生成或手工对齐，
  双端各留一份「派生层」，禁止组件内写死色值（现有 `--zy-glass-*` 派生方式继续沿用，方向正确）。
- **验收**：学生端、管理端、logo 三处主色同源；grep 两端的十六进制色值命中数降到白名单内。

### 3.1 信息架构与首屏路径

现状骨架已正确（tabBar 五区：首页/社区/**开始**/小组/我的），问题在页内层级。重排目标：
**任何状态下，用户 3 步内能进入「倾诉」或「创作」**（NFR-07）。

- 首页只回答三个问题：「我现在感觉如何（打卡）→ 我现在可以做什么（主行动）→ 我最近在变好（旅程摘要）」。
  其余内容（课程、活动、非遗馆）全部收进「开始」与「探索」二级。
- 闭环衔接物化：对话结束 → 推荐卡（已有）；推荐卡 → 创作（已有）；
  创作完成 → 发布（已有）；**补最后一环：作品收到第一个留暖 → 通知 → 回到社区**（依赖 T1.7）。
- 「开始」页升级为模式选择器：自由倾诉 / 经纬一刻（10–15 分钟练习）/ 呼吸正念，
  与 L4 旗舰闭环对齐，不再新增第四个入口。

### 3.3 核心页面重做方案

每页写明：**要解决的具体问题 → 方案 → 完成定义**。

**P-1 首页**
- 问题：6 卡片平铺主次不分（优化建议书 L2）；打卡与主行动割裂；`hasNotice` 假角标；装饰性英文小标题。
- 方案：三段式——①渐变问候+心情选择（选完直接改写②的文案）；②单一主行动卡（「和小织聊聊」或「继续昨晚的扎染」，取最近未完成会话）；③今日推荐一组横滑+旅程摘要一行。通知角标接 T1.7 真实数据。
- 完成定义：320px/390px 无溢出；新用户 10 秒内能找到主行动（可找 3 个非项目同学实测）；无硬编码色值。

**P-2 对话页**（与 T1.3 绑定）
- 问题：假流式体感；欢迎语/消息/高危卡/错误重试混在同一滚动区（建议书 L4）；免责声明占位行；语音输入入口不显眼。
- 方案：三段式 flex——顶部「小织·正在倾听」状态条（连接中/思考中/回应中三态，即使选 T1.3-B 也有真实等待反馈）；中部纯消息流，欢迎语为首条系统卡，高危卡与错误重试为覆盖层；底部吸底输入栏（麦克风/输入/发送）+ 极小字免责声明。
- 完成定义：断网→重试不丢已输入内容；高危触发时关怀卡不打断消息流位置；键盘全程可用（H5）。

**P-3 创作页**
- 问题：6 按钮平铺打断专注（建议书 L3）；心流判定只改一个提示条，没有真正「减少打扰」；呼吸动画突兀。
- 方案：全屏沉浸——顶部仅进度点+「更多」（暂停/放弃/帮助收进去）；中部步骤图文/音频；底部单一主按钮「下一步→完成创作」。`inFlow=true` 时自动隐藏更多按钮与吸底栏外一切装饰；`needBreathing` 时呼吸动画以底部抽屉滑出而非弹窗。完成保留庆祝层+回顾表单（已有）。
- 完成定义：心流态下屏幕可点击元素 ≤3 个；30 秒心跳机制不变（契约不动）；真实设备横竖屏切换不丢进度。

**P-4 作品详情页**
- 问题：发布者与观看者视角混排；留暖审核状态对作者不可见历史曾修复但视觉弱；缺图/视频失败态不一致。
- 方案：观看者视角以作品图/视频+故事为主，互动栏吸底；作者视角增加状态条（待审核/已通过/已下架）与「我的作品」返回；统一 MediaVideo 与缺图小织态。
- 完成定义：作者能一眼看到自己作品的审核状态；私密作品分享按钮禁用且有解释；加载失败可重试。

**P-5 我的页**
- 问题：功能清单式罗列，旅程感弱。
- 方案：顶部身份区→旅程三指标（创作天数/作品数/专注时长）→徽章横滑→菜单分区（记录/隐私/支持/设置）。
- 完成定义：与首页③旅程摘要数据同源；隐私与安全入口两步可达。

### 3.4 状态系统与边界

- StateBlock 组件覆盖：空（插画+一句引导+主行动）、错（原因+重试）、加载（骨架）。
  首批替换：首页推荐、社区列表、小组列表、我的作品、消息/通知。
- 无横向溢出：所有页面 320px 走查；吸底栏 `env(safe-area-inset-bottom)`；长文本 `word-break`。
- 暗色：学生端本期不做完整暗色（只做夜间模式页面级：音乐/呼吸/睡前），管理端已有 dark 基调。

### 3.5 管理端：在现有工程上继续深化（主路线），迁移 scaffold-master 退为备选

**判断：主路线是深化，不是迁移。** scaffold-master 已经把最值钱且最便宜的一层（视觉语言）给了这个项目，
剩下它独有的两层（组件封装、交互编排）都可以**用它的思路、在 Vben+Element Plus 上自己长出来**，
不需要吞下整个框架替换的代价。

#### 3.5.1 深化路线（四步，按依赖排序）

**第一步：造 `ZyListPage` 列表页封装（最高优先级，3–5 天）**

- 做什么：把 20 个业务列表页重复的「筛选区（可折叠）→ 操作栏 → el-table → 分页 →
  空/错/加载」收敛为一个组件 + 一个 composable（思路对标 scaffold 的 `ListPage`/`useListPage`，
  但基于 Element Plus，不引入 scaffold 代码）。DataState、TablePagination 作为内件复用。
- 试点三页：`users.vue`、`works.vue`、`comments.vue`（数据形态各异，能暴露封装缺口）。
- 完成定义：三页模板行数各减少 ≥40%；筛选/分页/刷新行为三页一致；键盘可用；
  typecheck 通过；旧实现保留在 git 历史，逐页可回退。

**第二步：珍珠输入体系组件化并推广（2–3 天）**

- 把只用于登录页的 `.zy-field`/`.zy-input-shell` 封装为 `ZyFormField` 组件（label/错误优先/
  hint/清空/显隐，接 el-form 校验），推广到项目编辑、活动发布、配置页等全部业务表单。
- 完成定义：业务表单不再出现裸 el-input+自定义样式混写；错误定位与焦点行为与登录页一致。

**第三步：交互编排层（3–4 天，全部 CSS+Vue Transition，不引入 GSAP）**

- 路由转场：按导航层级区分（同级淡入、下钻 slide-up），用 Vben 的 transition 钩子统一；
- 列表/卡片入场错峰：推广现有 `zy-stagger` 到全部列表页与看板卡；
- KPI 数字滚动：从「位移假滚动」改为 requestAnimationFrame 数字插值（保留 tabular-nums 防抖）；
- 图表就绪交叉淡入：DataState → 图表的 loading 交叉淡化，消除白块跳变；
- 图表点击下钻：OperationsChart 点击分类 → 跳转带筛选的对应列表页（收口 ui-ux-review 遗留项）。
- 完成定义：`prefers-reduced-motion` 下全部静态；滚动列表无掉帧（不铺 backdrop-filter 的纪律延续）；
  每个动效都能在 animations.scss/组件内找到唯一实现。

**第四步：令牌收敛（2 天，依赖待拍板④主色定案）**

- 管理端 indigo 收敛到品牌色族；`--zy-*` 与 `design/tokens.json` 单一事实源对齐；
  preferences.ts 默认主题同步；已保存的用户偏好提示重置。
- 完成定义：管理端主色与学生端、logo 同源；暗色阶单独评审通过。

#### 3.5.2 迁移 scaffold-master（备选，仅在触发条件成立时启动）

- 成本：20+ 页面用自研组件库重写 + 权限体系重建 + ECharts 重新接入，**4–6 周**，期间管理端冻结。
- 回退：全有或全无，只能 Git 分支整体回退。
- **触发条件（满足任意两条才值得谈迁移）**：
  ① Vben monorepo 的 typecheck/build 时长失控，日常开发被显著拖慢；
  ② Element Plus 表格/表单能力被证明不够（出现绕不过去的二次封装补丁层）；
  ③ 决定长期维护自有组件库、把管理端做成独立品牌产品而非内部工具；
  ④ Vben 主版本升级造成大面积破坏性适配。
- 在此之前，迁移是纯粹的重复投资。

## 5. 小织形象重设计

### 5.1 定位与人格

- 定位：**陪伴者，不是装饰**。三个不允许：不允许遮挡内容（现行悬浮可拖动方案改为「内嵌为主、悬浮可选」，
  与 ui-guidelines 2026-10 统一版 L8 一致）；不允许暧昧化措辞；不允许在中性场景（呼吸/白噪音/睡前）强行出现。
- 人格关键词：温和、手巧、慢一点。话术边界已由 prompt 约束，形象要匹配「手作人」而非「虚拟偶像」。

### 5.2 造型语言

- **保留可识别资产**：薄荷青色系、双丸子头可以保留为剪影记忆点——但造型做减法。
- **一个记忆点原则**：胸前交织线构成的心形（呼应 logo 的交织双线），全形象只允许这一个非遗符号；
  **不堆砌纹样**（不在衣服上印刺绣图案、不加盘扣流苏等装饰细节——缩小后全是噪点）。
- 线条：粗描边（≥6px@512 画布）、圆头、几何化脸型；色彩 ≤4 色（薄荷青主、暖金一点、米白、深灰蓝描边）。
- 这一版的目标不是「更萌」，是「缩小到 48px 仍然清楚、放大到 400px 不失真」。

### 5.3 表情与动作集（8 态）

idle / blink / talk / thinking / caring / happy / celebrate（完成作品）/ sleep（睡前模式）。
映射现有触发点：sendMessage→thinking、首 token→talk、危机→caring、完成→celebrate、夜间→sleep。
现有 6 态可直接映射前 6 态，新增 celebrate/sleep。

### 5.4 场景与尺寸用法

| 场景 | 尺寸 | 形式 |
|---|---|---|
| 对话页头像/状态条 | 64–96px | 静态帧 + talk 双帧切换 |
| 首页内嵌卡（XiaozhiCard） | 120–160px | 静态 + CSS 呼吸浮动 |
| 空/错/加载状态 | 160–200px | 单帧插画（穿针/线团/补丁三幅） |
| 完成庆祝 | 240px | celebrate 帧 + CSS 粒子，不用重型动画库 |
| 管理端登录页 | 200px | 单帧 |

### 5.5 技术实现匹配

- **格式：统一 512×512 画布 PNG 序列帧（同源 SVG 导出）**。不用 Lottie——小程序端需要额外运行时
  且 8 态 × 2–3 帧的序列帧总量可控（目标单帧 ≤30KB，WebP 优先、PNG 兜底）。
- 动效一律 CSS transform/opacity（眨眼用帧切换、浮动用 translateY），不引 JS 动画库；
  `prefers-reduced-motion` 下全部静态。
- 修复现有痛点：6 张旧图画布不齐 → 新资产从同一 SVG 模板导出，物理对齐，根治「眨眼缩小感」。

### 5.6 资产清单与产出方式

- 清单：1 个 SVG 母版 + 8 状态帧 + 3 幅状态插画 + 1 个 48px 简化版（tabBar/头像级）。
- 产出方式两轨：**AI 生图出方向稿 → 人工（Photopea/Figma）统一重绘为正稿**。
  风险提示：①AI 直出多状态一致性差，不能直接当正稿；②建议书已指出旧图有 AI 水印与版权标注义务，
  新资产在「关于」页延续「形象由 AI 辅助生成」声明；③若答辩/商用要求更高，建议约稿插画师，
  成本换来的是完全版权与多状态一致性——**这是花钱能彻底解决的风险点**。
- 验收：48px 缩图可辨、6 态切换无位移抖动、包体积增量 ≤300KB、关于页声明更新、
  brand-assets.md 与 AGENTS.md §8.1 条款同步修订。
